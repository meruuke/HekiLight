## User Story

As a HekiLight developer, I want a `GetCCRotationData(profile, heroTalent)` function that reads the player's live ClassCodex rotation table and returns an ordered spellID list, so that subsequent stories can build the CC resolver on a confirmed, in-game-validated data contract.

## Background

This is a **spike story** — its sole purpose is to resolve the outstanding gap in EPIC-12: the exact `ClassCodexData` key structure for spec sub-entries is confirmed at the class level but requires in-game inspection to verify any sub-key structure (e.g., whether it is `ClassCodexData["DEMONHUNTER"]` flat or `ClassCodexData["DEMONHUNTER"]["havoc"]`).

No CC mode is activated in this story. The `/hkl ccdata` slash command is the in-game validation surface — it prints the resolved spell list to chat so the developer can confirm the data contract before any resolver code is written in Story 12.2.

**Reading `ClassCodexData` is zero-taint** — it is a plain Lua table exposed as a global, not an RA slot or action bar call. No pcall is required for the table read itself, though the overall function is pcall-guarded at the call site.

**Prior story context (11.2):** `Settings.lua` now exists and `HekiLight.lua` is ~2083 lines. All new functions in this story go into `HekiLight.lua` (the CC resolver module-level section), following the existing sectioned banner pattern.

## Acceptance Criteria

## Dev Notes

### Previous Story Insights
Story 11.2 extended `HekiLightST` to 21 keys and extracted `BuildSettingsPanel` to `Settings.lua`. `HekiLight.lua` is now ~2083 lines. The new functions in this story are **module-level locals** and do not need to be added to `HekiLightST` (they are not consumed by `Settings.lua`).

### Data Shape
From EPIC-12 research (2026-05-24):
```lua
-- Confirmed class-level key format:
ClassCodexData["DEMONHUNTER"].rotation = {
  {
    heroTalent = "Void-Scarred",
    context    = "Single Target",
    steps = {
      "{1245412} if you are about to enter {1217607}",
      "{1226019} at 74 fury or with a {1238495} proc",
    },
  },
  -- more profiles...
}
```
**Outstanding gap:** Whether `ClassCodexData["DEMONHUNTER"]` is flat (`.rotation` directly) or nested (e.g., `["havoc"].rotation`) is unconfirmed. `Task 2` DLog `CC_KEYMAP` resolves this spike.

### Key Resolution Strategy
```lua
-- Attempt 1: flat class key
local classToken = UnitClassBase("player"):upper()
local ccClass = ClassCodexData[classToken]
-- Attempt 2: if ccClass.rotation is nil, inspect ccClass for spec sub-keys
--   GetSpecialization() returns specIndex (1,2,3,4)
--   GetSpecializationInfo(specIndex) returns ..., specName, ...
--   try ccClass[specName:lower()] or ccClass[specIndex]
-- Log discovered structure to DLog("CC_KEYMAP", ...)
```

## Business Value

Resolves the only outstanding data-contract risk in EPIC-12. All five subsequent stories (12.2–12.5) depend on knowing the exact `ClassCodexData` key structure. Without this spike, Story 12.2 would ship resolver code against an unconfirmed data shape and risk a silent `nil` table walk.
