## User Story

As a player who wants to show a specific key label on the HekiLight overlay, I want to press any key combination and have that label displayed for a spell — even if that key is not actually bound to the spell on any action bar — so I can use the overlay as a visual cue for whatever key I associate with that spell.

## Background

Story 10.3 added a slot-picker flow: select a spell → select a bar slot → HekiLight reads the keybind of that slot. This works well when the spell is on an action bar and the player wants to show its real binding.

However, players may want to display a label that doesn't correspond to any bar slot — for example, a mouse button they mentally associate with a spell, a key from a different profile, or simply a reminder label. The slot-picker cannot cover this case because `GetSlotKeybind` can only return bindings that WoW knows about.

This story adds a **keybind capture button** alongside the existing slot picker. Clicking it enters capture mode (same UX as the Mount Journal keybind capture: button shows "Press any key…", next non-modifier keypress is stored). The captured string is stored as a raw label, independent of any action bar slot.

### Priority order in `GetSpellKeybind`

```
1. dbChar.keybindLabels[spellID]   — custom captured label (this story)
2. dbChar.keybindOverrides[spellID] — slot-derived label (Story 10.1/10.3)
3. FindSpellActionButtons auto-detect (existing)
4. keybindCache fallback (existing)
```

### UI layout in Keybind Overrides section (after this story)

```
[kbSpellDD: Select a rotation spell…]
[kbSlotDD: Select a bar slot…]  [Pin keybind]          ← existing (Story 10.3)
[Capture Keybind]                                       ← new button (this story)
─────────────────────────────────────────────────────
[icon] Spell Name [spellID]  Label: C-1        [Clear]  ← label-type entry
[icon] Spell Name [spellID]  Slot 3 -> 2       [Clear]  ← slot-type entry
No keybind overrides set.
```

## Acceptance Criteria

- [ ] **AC1 — `keybindLabels` initialised in `InitDB`:** `dbChar.keybindLabels` is initialised as `{}` if nil, immediately after `keybindOverrides` init. Existing saves are not overwritten.

- [ ] **AC2 — `GetSpellKeybind` checks `keybindLabels` first:** Before the `keybindOverrides` check, read `dbChar.keybindLabels[spellID]`. If non-empty, populate `keybindCache[spellID]`, log `DLog("KEYBIND", "spellID=%d key=%s source=label")`, and return the label string. Fall through to `keybindOverrides` if absent or empty.

- [ ] **AC3 — Capture button in Keybind Overrides section:** A button labeled `L["Capture Keybind"]` is placed in `kbBody`, below the slot picker row (`TOPLEFT(-2, -86)` or adjusted to sit cleanly below `kbSlotDD`). It is visible whenever a spell is selected in `kbSpellDD` (same visibility rule as the slot picker row). Its initial label shows the current custom label for the selected spell if one exists, e.g. `"C-1 (captured)"`, otherwise `L["Capture Keybind"]`.

- [ ] **AC4 — Capture mode on click:** Clicking the capture button:
  1. Changes its text to `L["Press any key…"]`
  2. Creates (or shows) an invisible full-screen intercept frame with `EnableKeyboard(true)` and `SetScript("OnKeyDown", captureHandler)`
  3. Captures the first non-modifier-only keypress (ignore presses where the key is solely SHIFT, CTRL, ALT, or META)
  4. Runs the captured key through `FormatKey()` to produce a short label (e.g., `"C-1"`, `"F"`, `"A-Mouse Button 5"`)
  5. Stores `dbChar.keybindLabels[selectedKbSpellID] = label`
  6. Updates the button text to the captured label
  7. Hides the intercept frame

- [ ] **AC5 — Escape cancels capture:** If the intercepted key is `"ESCAPE"`, cancel capture without storing anything. Restore the button to its pre-capture label. Hide the intercept frame.

- [ ] **AC6 — Override list distinguishes label vs slot entries:** `RefreshKbOverrideList` checks both `dbChar.keybindLabels` and `dbChar.keybindOverrides`. For each spell that has either:
  - If `keybindLabels[sid]` is set: show `"Label: " .. label` in the row text.
  - Else if `keybindOverrides[sid]` is set: show existing `"Slot N -> Key"` format.
  - A spell appears only once even if both are set (label takes priority in display too).

- [ ] **AC7 — Clear removes both overrides:** The row's Clear button sets `dbChar.keybindLabels[sid] = nil` AND `dbChar.keybindOverrides[sid] = nil`, then calls `RefreshKbOverrideList()`. The capture button resets to `L["Capture Keybind"]` if the cleared spell is currently selected.

- [ ] **AC8 — `/hkl kb label <spellID> <key>` slash command:** Parses `<key>` as a raw key string (e.g., `"ctrl-1"`, `"alt-f2"`, `"shift-mouse button 3"`), runs it through `FormatKey()`, stores in `dbChar.keybindLabels[spellID]`. Prints confirmation: `[HekiLight] Label for Frostbolt set to "C-1"`. Rejects non-numeric spellID with a clear error.

- [ ] **AC9 — `/hkl kb clear <spellID>` updated:** The existing command now also nils `dbChar.keybindLabels[spellID]` in addition to `dbChar.keybindOverrides[spellID]`. Print message reflects both were cleared.

- [ ] **AC10 — `/hkl kb list` shows label entries:** Entries where `keybindLabels[sid]` is set are shown with `"(label)"` suffix, e.g.: `Frostbolt [116]: C-1 (label)`. Slot overrides continue to show `"(slot N)"`.

- [ ] **AC11 — No taint:** The keyboard intercept frame is created once at `ADDON_LOADED`, parented to `UIParent`, starts hidden. `EnableKeyboard(true/false)` is toggled only during active capture. No protected frame ancestry.

- [ ] **AC12 — In-game verification:** Select a spell in the Keybind Overrides section. Click "Capture Keybind". Press `Ctrl+1`. Button shows `"C-1"`. Overlay label for that spell updates on next tick to `"C-1"` without `/reload`. Press Escape during a second capture attempt — button reverts, nothing stored. Click Clear — both label and any slot override are removed, overlay reverts to auto-detect.

**`captureHandler` pattern:**

```lua
local MODIFIER_ONLY = { LSHIFT=true, RSHIFT=true, LCTRL=true, RCTRL=true,
                         LALT=true, RALT=true, LMETA=true, RMETA=true }

local function captureHandler(_, key)
    if MODIFIER_ONLY[key] then return end  -- ignore bare modifier presses
    kbCaptureFrame:Hide()
    kbCaptureFrame:EnableKeyboard(false)
    if key == "ESCAPE" then
        UpdateCaptureBtn(selectedKbSpellID)  -- restore label, no store
        return
    end
    local mods = ""
    if IsShiftKeyDown() then mods = "SHIFT-" .. mods end
    if IsControlKeyDown() then mods = "CTRL-" .. mods end
    if IsAltKeyDown() then mods = "ALT-" .. mods end
    local raw = mods .. key
    local label = FormatKey(raw)
    dbChar.keybindLabels[selectedKbSpellID] = label
    kbCaptureBtn:SetText(label)
    RefreshKbOverrideList()
    print(string.format("|cff88ccff[HekiLight]|r Label for spellID %d set to \"%s\"", selectedKbSpellID, label))
end
```

**`UpdateCaptureBtn` helper:**

```lua
local function UpdateCaptureBtn(spellID)
    if not kbCaptureBtn then return end
    local label = spellID and dbChar.keybindLabels and dbChar.keybindLabels[spellID]
    kbCaptureBtn:SetText(label and (label .. " " .. L["(captured)"]) or L["Capture Keybind"])
end
```

**`RefreshKbOverrideList` merge logic:**

```lua
-- Collect all spellIDs that have either a label or a slot override
local seen = {}
for sid in pairs(dbChar.keybindLabels or {}) do seen[sid] = true end
for sid in pairs(dbChar.keybindOverrides or {}) do seen[sid] = true end
-- Render each: label takes priority
for sid in pairs(seen) do
    local label = dbChar.keybindLabels[sid]
    local displayText
    if label and label ~= "" then
        displayText = "Label: " .. label
    else
        local slot = dbChar.keybindOverrides[sid]
        local key = slot and GetSlotKeybind(slot) or "(unbound)"
        displayText = "Slot " .. (slot or "?") .. " -> " .. key
    end
    -- ... render row with displayText and Clear button
end
```

## Business Value

Players who use non-standard keybind setups (mouse buttons, hardware macro keys, off-bar bindings) cannot use the slot-picker because WoW doesn't expose those bindings through `GetBindingKey`. The capture button lets them pin any label they want, making the keybind display meaningful for 100% of input configurations.
