## User Story

As a developer maintaining HekiLight, I want `BuildSettingsPanel` and `BuildIgnorePanel` to live in a dedicated `Settings.lua` file, so that settings-only stories no longer require reasoning about the full 2476-line `HekiLight.lua` and merge conflicts between concurrent stories are reduced.

## Background

`HekiLight.lua` has grown to ~2476 lines. The Settings Panel (`BuildSettingsPanel` + `BuildIgnorePanel`, lines ~717–1529, ~812 lines) is the largest single section and the most isolated from the hot-path — it executes only at `ADDON_LOADED`, never during combat.

Story 11.1 shipped the `HekiLightST` addon-global namespace that exposes all module-level locals `Settings.lua` will need. This story performs the extraction: move the two functions to `Settings.lua`, replace every direct local reference inside them with `HekiLightST.*`, and wire the new file into the TOC load order.

**No behavioral change.** `BuildSettingsPanel()` and `BuildIgnorePanel()` are still called at `ADDON_LOADED` from the event handler in `HekiLight.lua`. Call sites are unchanged. The result is pixel-for-pixel identical to the pre-extraction state.

## Dev Notes

**Files changed:**
- `HekiLight.lua` — section removed (~812 lines deleted), TOC untouched by this file
- `HekiLight.toc` — one line added (`Settings.lua`)
- `Settings.lua` — new file, ~812 lines

**Extraction range in `HekiLight.lua`:**
Per EPIC-11 architectural analysis: `BuildSettingsPanel` starts at approximately line 717 and `BuildIgnorePanel` ends at approximately line 1529 (~812 lines total). Verify exact boundaries before cutting — the extraction range starts at the `local function BuildSettingsPanel()` line and ends at the closing `end` of `BuildIgnorePanel`.

**TOC entry (exact addition):**
```
## Interface: 120005
...
Locale.lua
HekiLight.lua
Settings.lua        ← add this line
```

**`HekiLightST` is populated at `ADDON_LOADED` (inside `InitDB()`)** — Story 11.1 guarantees it is populated before `BuildSettingsPanel()` is called. The TOC load order ensures `HekiLight.lua` (which declares `HekiLightST` and calls `InitDB()`) executes before `Settings.lua` loads. `Settings.lua` only defines functions — it does not call them at parse time.

**Substitution safety rule — avoid false positives:**
The bare name `db` appears in many contexts (e.g., variable names like `dbChar`, string literals). Use whole-word grep patterns (e.g., `\bdb\b`) to find only true references. `L` is a single letter — search for `L["` and `L[L` patterns rather than bare `L` to avoid false matches in string literals.

**`Apply*` functions:** These are defined in `HekiLight.lua` after `BuildSettingsPanel`. In `Settings.lua` they are accessed as `HekiLightST.ApplySlotLayout(...)` etc. — the `HekiLightST` table holds references to the live functions, so calls work correctly.

**Call sites that must NOT be removed from `HekiLight.lua`:**
```lua
-- Inside events OnEvent, ADDON_LOADED branch:
BuildSettingsPanel()
BuildIgnorePanel()
```
These calls remain in `HekiLight.lua`. Since `Settings.lua` is loaded after `HekiLight.lua` (per TOC), both functions are defined by the time `ADDON_LOADED` fires.

**Testing (in-game only):**
- `/reload` → Lua error frame empty

- `/hkl scale 1.5` then `/hkl scale 1.0` → verify scale applies
- `/hkl ignore 12345` → verify appears in Ignored Spells list
- `/hkl kb pin 12345 1` → verify appears in Keybind Overrides list (if spell is on bar slot 1)
