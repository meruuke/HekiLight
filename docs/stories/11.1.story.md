## User Story

As a developer working on HekiLight, I want a stable `HekiLightST` addon-global table that exposes the module-level locals that `Settings.lua` will need, so that EPIC-11 Story 11.2 can safely read shared state across files without breaking the single-file runtime that exists today.

## Background

`HekiLight.lua` is a ~2476-line single-file addon. All state is module-level locals. WoW's Lua runtime has no `require()` — inter-file communication must go through addon-globals. Before any code can be moved to `Settings.lua`, the locals it depends on must be reachable from that file.

This story is a **prerequisite spike**: it ships the `HekiLightST` namespace and verifies it is correctly populated at `ADDON_LOADED`, with zero behavioral change. Story 11.2 then reads from it.

`HekiLightST` holds **references**, not copies. Because `db` and `slots` are tables, `HekiLightST.db` points to the same table that `Refresh()` reads — writes from `Settings.lua` are immediately visible to the hot path with no synchronisation needed (ADR-11-1).

## Dev Notes

**File:** `HekiLight.lua` only — no other files change in this story.

**Where `InitDB()` lives:** "Helpers" section (per CLAUDE.md section table). It is the first function defined after the module-level locals block.

**Global declaration placement:**
```lua
-- TOP OF FILE — before any local declaration
HekiLightST = {}

-- then existing locals follow:
local DEFAULTS = { ... }
local db, dbChar
-- etc.
```

**Why `Refresh` needs a closure:**
`Refresh` is defined later in the file than `InitDB`. In Lua, assigning `HekiLightST.Refresh = Refresh` inside `InitDB()` would capture `nil` because `Refresh` is not yet assigned at that point. The closure `function() Refresh() end` defers the lookup to when the wrapper is actually called, by which time `Refresh` is defined. All other values (`db`, `dbChar`, `slots`, etc.) are tables/functions assigned before or during `InitDB()`, so direct reference assignment is safe for them.

**Population block (copy verbatim):**
```lua
-- End of InitDB() — expose shared state for Settings.lua (EPIC-11)
HekiLightST.db                  = db
HekiLightST.dbChar               = dbChar
HekiLightST.display              = display
HekiLightST.slots                = slots
HekiLightST.procAlertFrame       = procAlertFrame
HekiLightST.cachedRotSpells      = cachedRotSpells
HekiLightST.Refresh              = function() Refresh() end
HekiLightST.ApplySlotLayout      = ApplySlotLayout
HekiLightST.ApplyKeybindStyle    = ApplyKeybindStyle
HekiLightST.ApplyKeybindAnchor   = ApplyKeybindAnchor
HekiLightST.ApplyProcAlertLayout = ApplyProcAlertLayout
HekiLightST.ApplyPosition        = ApplyPosition
HekiLightST.L                   = L
```

**Testing (in-game only — no test suite):**

- Settings panel: open, all 5 sections visible, interact with dropdowns

## Business Value

Unblocks Story 11.2. Without the namespace, any extracted `Settings.lua` would read `nil` for all shared locals. This is the safest possible change — additive only, zero behavioral impact.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| `Refresh` closure captures stale nil if called before `Refresh` is defined | Very Low | High | `InitDB()` is called at `ADDON_LOADED`; `Refresh` is defined at file parse time (before any event fires). The closure resolves at call-time, not assignment-time. |
| `HekiLightST` name collides with another addon's global | Very Low | Medium | Name is addon-prefixed; WoW convention. No known conflict. |
| Population block placed inside wrong scope (local instead of global) | Low | High | Verify with `/script print(HekiLightST)` after `/reload` — should print `table: 0x...`, not nil. |

## Definition of Done

`/script print(HekiLightST.db, HekiLightST.Refresh)` after `/reload` prints a table address and a function address. No Lua errors. Settings panel unchanged.
