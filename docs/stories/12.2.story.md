## User Story

As a HekiLight user with ClassCodex installed, I want `GetCCSuggestion()` and `GetCCSuggestionQueue(n)` to drive the HekiLight display when CC mode is enabled (`db.ccEnabled == true`), so that spell suggestions on screen reflect ClassCodex priority order rather than Blizzard's Rotation Assistant.

## Background

Story 12.1 delivered `GetCCRotationData(profile, heroTalent)` and `ParseCCSteps(steps)` — the data-reading layer is confirmed and validated in-game. This story builds the resolver layer: two CC-mode counterparts to `GetActiveSuggestion()` and `GetSuggestionQueue(n)`, plus the routing logic in `Refresh()` that switches between the RA and CC pipelines.

Three new `DEFAULTS` keys are stubbed here (`ccEnabled`, `ccProfile`, `ccHeroTalent`) and will be wired to the Settings UI in Story 12.3. For now they are toggleable only via `/script HekiLightDB.ccEnabled = true`.

**Core design principle:** The CC resolver reuses every downstream piece of the existing pipeline unchanged — `GetRealSlot`, `IsUsableAction`, `C_Spell.GetSpellCooldown`, `GetSpellBaseCooldown`, `queueCache`/`queueCount`, and the display's `realSlotID`-based in-range tinting, proc glow, and keybind lookup. The only new code is the priority-list walker and the routing branch in `Refresh()`.

## Acceptance Criteria

- [ ] **AC1 — CC mode display** — When `db.ccEnabled == true` and ClassCodex data is available for the current spec, the HekiLight primary slot shows the first mechanically castable spell from the ClassCodex priority list in order.
- [ ] **AC2 — Greyed secondary slots** — On-cooldown spells from the CC priority list appear in secondary slots (greyed out), matching the two-pass behavior of `GetSuggestionQueue`.
- [ ] **AC3 — Full downstream pipeline preserved** — In-range tinting, proc glow, and keybind labels all continue to function correctly (same `realSlotID` pipeline, no changes to display or downstream functions).
- [ ] **AC4 — Graceful fallback** — When `db.ccEnabled == true` but CC data is unavailable for the current spec, the suggestion pipeline silently falls back to RA mode (`GetActiveSuggestion` / `GetSuggestionQueue`). No error, no blank display.
- [ ] **AC5 — `CC_FALLBACK` DLog** — `DLog("CC_FALLBACK", ...)` fires when fallback occurs; change-detection guard prevents it from firing on every poll frame — fires only when spec changes or the CC-enabled state transitions.
- [ ] **AC6 — No Lua errors** — Zero Lua errors in the Blizzard error frame during normal combat with CC mode on or off.

### CC_FALLBACK Change-Detection Pattern

`lastCCFallbackSpec` (module-level, init `0`) stores the last spec index at which `CC_FALLBACK` was logged. On each `Refresh()` where CC data is unavailable:
```lua
local spec = GetSpecialization()
if spec ~= lastCCFallbackSpec then
    DLog("CC_FALLBACK", ...)
    lastCCFallbackSpec = spec
end
```
Reset to `0` in the `else` branch (CC disabled) so the next CC-enable cycle logs correctly.

### Technical Constraints

- All `GetRealSlot` and `C_Spell.GetSpellCooldown` calls inside CC variants must be pcall-guarded — same rule as existing RA pipeline [Source: CLAUDE.md §Key conventions]
- Do NOT use `C_CooldownViewer` (ADR-6, permanently off-limits) [Source: CLAUDE.md]
- `queueCache`/`queueCount` are the same vars used by `GetSuggestionQueue` — this is intentional; CC and RA queue functions never execute in the same frame

## Business Value

Delivers the functional CC mode end-to-end path: ClassCodex priority list → on-screen spell suggestion. With Stories 12.1 (data reader) and 12.2 (resolver) complete, CC mode is testable in combat even before the Settings UI (Story 12.3). Stories 12.3–12.5 build directly on this resolver layer.
