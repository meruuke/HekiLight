# Story 13.1: Per-Character Session Log with History Retention

**Status:** Draft
**Epic:** 13 — Logging & Observability Improvements
**Version:** TBD
**Priority:** Medium
**Complexity:** S

## Context

`HekiLightDB.sessionLog` is account-wide. Every time the addon loads (login, `/reload`, character switch), the current `sessionLog` is moved to `lastSessionLog` and a new empty ring buffer starts. This means switching characters permanently discards the previous character's log — only one session of history survives at a time across all characters.

This was discovered while trying to verify EPIC-6 story 6.1 (shapeshift keybind fix): the Druid session's `KEYBIND` DLog entries were lost after switching to a Warlock, making post-session log analysis impossible.

## Acceptance Criteria

- [ ] Session log is stored in `HekiLightDBChar.sessionLog` (per-character) instead of `HekiLightDB.sessionLog`
- [ ] `HekiLightDBChar.lastSessionLog` holds the previous session for that character
- [ ] Switching characters leaves each character's log intact and readable on next login
- [ ] `/hkl log [N]` reads from `HekiLightDBChar.sessionLog` (current session)
- [ ] `/hkl log last [N]` (new or existing) reads from `HekiLightDBChar.lastSessionLog`
- [ ] `DLog(tag, msg)` writes to `dbChar.sessionLog` instead of `db.sessionLog`
- [ ] Ring buffer cap (500 entries) preserved per character
- [ ] No change to DLog tag names, format, or behaviour
- [ ] Old `HekiLightDB.sessionLog` / `lastSessionLog` keys cleaned up from existing SavedVariables on first load

## Implementation Notes

- In `InitDB()`, initialise `HekiLightDBChar.sessionLog = {}` and `HekiLightDBChar.lastSessionLog = {}`
- On `ADDON_LOADED`, move `dbChar.sessionLog` → `dbChar.lastSessionLog` before starting fresh (same pattern as current account-level rotation)
- Update `DLog()` to append to `dbChar.sessionLog` instead of `db.sessionLog`
- Update `/hkl log` handler to read from `dbChar.sessionLog` / `dbChar.lastSessionLog`
- Remove `HekiLightDB.sessionLog` and `HekiLightDB.lastSessionLog` from `DEFAULTS` and from the account-level `InitDB` path
- Migration: on first load after the change, `db.sessionLog` will be a stale key — safe to leave (WoW ignores unknown SavedVariable keys); no explicit migration needed

## Scope

**IN:** Move sessionLog and lastSessionLog to `HekiLightDBChar`; update `DLog`, `InitDB`, and `/hkl log` handler.
**OUT:** No changes to DLog tags, ring buffer size, log format, or any other slash command.

## Files to Change

- `HekiLight.lua` — `InitDB()`, `DLog()`, `ADDON_LOADED` handler, `/hkl log` slash command handler
